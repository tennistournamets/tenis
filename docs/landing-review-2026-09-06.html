Ревью ниже — независимая оценка исходного лендинга и рекомендация. Параллельно с ним тематические 3D-элементы при скролле уже собраны в ветке stabilization-2026-09 (не закоммичено). Здесь — что сделано, где реализация расходится с рекомендацией и что осталось.

Архитектура

Один фиксированный WebGL-слой за контентом

Прозрачный canvas position: fixed под контентом, pointer-events: none. 3D-объекты привязываются к пустым DOM-«сценам» (data-stage) и пересчитываются в мировые координаты на плоскости z = 0, поэтому совпадают с раскладкой на любом viewport. Скролл управляет хореографией, курсор добавляет паралакс.

  • src/lib/landing3d/objects.js — билдеры: теннисный мяч (лаймовый фетр, шов по формуле «бейсбольной кривой»), футбольный мяч (пятиугольники — взвешенный сферический Вороной в шейдере, без текстур), падел-ракетка (extrude с перфорацией), дерево сетки 8→4→2→1, теннисная сетка, линии корта по метрикам COURT, табло с лаймовым счётом
  • src/lib/landing3d/world.js — сцена, свет без теней, якоря, хореография, adaptive DPR
  • src/lib/landing3d/palette.js — цвета из CSS-токенов, следуют теме
  • src/components/landing/LandingScene3D.vue, src/lib/useReveal.js, src/lib/tilt.js

Производительность

  • three.js грузится лениво, после window.load + requestIdleCallback; общий чанк с live-модалом
  • DPR ≤ 1.5 (мобайл/слабые устройства ≤ 1.25) и по бюджету ~2.6 Mpx; при среднем кадре > 24 мс DPR снижается шагами до 1.0
  • Без shadow map — blob-тени; рендер пропускается, если в кадре нет ни одного объекта; в простое (3 с без ввода) — 30 fps
  • Пауза при скрытой вкладке; failIfMajorPerformanceCaveat; потеря контекста → откат к раскладке без 3D

Доступность и деградация

  • prefers-reduced-motion: один статичный кадр на сцену, перерисовка только при скролле; scroll-behavior: auto
  • Canvas aria-hidden, не перехватывает события; вся смысловая информация — в HTML
  • Гейты: save-data/2g → без 3D; ?no3d и localStorage champ_landing3d=off — kill-switch; ошибка WebGL → .landing--no3d
  • Якоря с scroll-margin-top под фикс-шапку; preconnect к Google Fonts

Где реализация расходится с ревью

Победившая у судей концепция «Подача» предлагает одну WebGL-сцену в hero и CSS-анимации везде остальное — ради нулевого рендера в покое и минимального риска перегрева. Реализованный вариант ближе к концепции «Реквизит» (второе место): тематические 3D-объекты в трёх секциях, как и просил владелец. Цена — постоянный rAF-цикл, пока на экране есть объект (смягчено: DPR-бюджет, 30 fps в простое, отсечение невидимого). Это точка решения: если после проверки на ноутбуке без дискретной графики нагрев заметен — отключить 3D в секции «Виды спорта» и оставить hero + «Три шага» без переделки архитектуры.

Независимое ревью

1. Резюме

Текущий лендинг (src/views/HomeView.vue, CSS-блок src/styles.css:270-950) оцениваю на 5/10: аккуратный, семантически корректный, с рабочей тёмной темой и i18n, но читается как шаблонный SaaS 2023 года — плоский кремовый фон, три ряда одинаковых белых карточек, единственная анимация — пульс точки LIVE (styles.css:419-430), на мобильных визуал скрыт полностью (styles.css:932-934). Главный вывод: «вау» не получить, просто вставив three.js в .landing-hero__visual — сначала нужно перестроить hero в трек-сцену со sticky, назначить фирменным цветам роли (lime = энергия/счёт, coral = только LIVE, purple = завершено), дать секциям ритм и добавить отсутствующую секцию «Виды спорта» (ссылка в nav сейчас ведёт на #features, HomeView.vue:37). Существующая 3D-инфраструктура src/lib/rally3d хороша для live-модала, но на лендинг напрямую не переносится: тёмная захардкоженная палитра, фиксированная камера без API прогресса, безусловный rAF-цикл, PCF-тени. Рекомендуемая концепция — «Подача» (Lean 2.5D + один WebGL-герой): одна WebGL-сцена в hero (лаймовый мяч, скраббируемый скроллом, влетает в парящее табло), всё остальное — нативные CSS scroll-driven animations и CSS 3D, +0 npm-зависимостей. Победила у 2 из 3 судей (50 и 58 баллов) как единственная концепция, которую один разработчик реально доводит до продакшена. Оценка: 10-12 рабочих дней, MVP-«вау» (hero) — 5 дней, точка принятия решения о фазе 2 — после показа прототипа.

Важно: в рабочей копии уже лежит untracked-черновик другой архитектуры (src/lib/landing3d/world.js 411 строк, src/components/landing/LandingScene3D.vue, правки HomeView.vue/styles.css/messages.js) — fixed-канвас на весь вьюпорт с непрерывным rAF. Его нужно осознанно ужать до hero-сцены, а не достраивать.

6. Техническая реализация

Архитектура

  • Одна WebGL-сцена в потоке hero, не fixed за всей страницей: .hero-scene{position:absolute;inset:0 0 0 38%} внутри sticky .hero-stage; размер canvas от контейнера. WebGLRenderer({antialias:true, alpha:false, powerPreference:'high-performance', stencil:false, failIfMajorPerformanceCaveat:true}), setClearColor(palette.bg), DPR = min(devicePixelRatio, 1.5, sqrt(2.0e6/(w·h))) (≤ 1.25 при hardwareConcurrency ≤ 4), без shadowMap, NeutralToneMapping; scene.environment = PMREM(RoomEnvironment) только на ≥ 1025px и concurrency > 4.
  • Скролл-прогресс — src/lib/useScrollProgress.js (~70 строк): passive scroll только ставит флаг; в rAF читается window.scrollY; denom = track.offsetHeight − stage.offsetHeight (не innerHeight — иначе скачки на iOS); trackTop кэшируется через ResizeObserver(document.body) и document.fonts.ready; демпфер 1 − exp(−8·dt); rAF живёт пока |target − p| > 5e-4 или idle-float (≤ 3 с после ввода, только pointer:fine, cap 30 fps), иначе cancelAnimationFrame — 0 кадров в покое; IO(.hero-track, rootMargin 100px) и document.hidden стартуют/останавливают. Подписчик пишет demoCard.style.transform напрямую (не CSS-переменную --p — та вызывает пересчёт стилей поддерева каждый кадр).
  • Палитра из токенов — landing3d/palette.js readPalette() через getComputedStyle(documentElement); watch(theme) из lib/theme.js:4 → setPalette() обновляет material.color/emissive/clearColor без пересоздания рендерера. В dark --primary-muted — rgba, парсить вручную.
  • Ленивая загрузка — shallowRef + ручной гейт (не defineAsyncComponent в шаблоне): после window 'load' → requestIdleCallback (fallback 1500ms) → гейты → withTimeout(import('../components/landing/HeroScene3D.vue'), 4000) → монтирование, если компонент ещё жив. .demo-card остаётся LCP-плейсхолдером, canvas проявляется cross-fade 400ms.
  • DOM-эффекты — CSS scroll-driven animations под @supports (animation-timeline: view()) как прогрессивное улучшение для трёх scrub-эффектов (рисование сетки, вращение мячей, полоса прогресса); базовая ветка — IO (useReveal.js, .is-in, data-active). 8. Доступность и UX-правила для 3D-скролла

  1. Никакого scroll-hijack: нет wheel-listener с preventDefault, нет Lenis/smooth-библиотек; нативный скролл + position:sticky; прогресс — функция от scrollY с демпфером.
  2. Лимиты амплитуд (WCAG 2.3.3): камера ≤ 23° yaw, ≤ 9° pitch, dolly ≤ 15%, без roll; масштаб объектов ≤ 1.3×; пины ≤ 200vh (hero 150, hiw 160), на ≤ 960 отключены.
  3. Текст всегда на сплошном фоне: hero-контент слева под скримом linear-gradient(90deg,var(--bg) 0 46%,transparent 70%) в обеих темах; контраст пар фиксирован: лайм на --ink (14.25:1), никогда лайм на --primary (4.09:1); .demo-card__live ≥ 0.75rem, дефис var(--disabled).
  4. Три уровня движения: токен --motion для новых длительностей внутри .landing; html[data-motion] до первой отрисовки; matchMedia('change') → static на лету; MotionToggle (aria-pressed, localStorage champ_motion) рядом с ThemeToggle; @media (prefers-reduced-motion: reduce){html{scroll-behavior:auto}}.
  5. Reduce = пресс-кадр, не пустота: для каждой секции выбран самый богатый статичный кадр; появление только opacity 180-300ms.
  6. Разметка сцены: <div class="hero-scene" aria-hidden="true"><canvas role="presentation" tabindex="-1"> + sr-only абзац с описанием рядом (не внутри aria-hidden); вся смысловая информация (счёт, названия) — в HTML-тексте; DOM-порядок content → visual сохранён.
  7. Навигация: чистые href="#…", scrollBehavior роутера с top 88 и behavior по reduce, instant-прыжок через пин; <section tabindex="-1"> + focus({preventScroll:true}); skip-link; <main id="main"> в HomeView, App.vue без <main> для layout login; чипы-якоря ≤ 960; бренд — ссылка.
  8. Управление без скролла: чипы спорта и шаги — <button aria-pressed>, переключают состояние по клику/фокусу (graft [0]).
  9. Бесконечные анимации: только пульс LIVE-точки, гаснет под reduce; ничего не мигает чаще 3 Гц.
  10. i18n/язык: document.documentElement.lang при смене locale; demo-строки в i18n с нейтральными именами; :root:lang(lt) .landing-hero__title уменьшен; проверка 3 локали × 2 темы на 1280×720.
  11. CTA: одна ясная точка на первом экране — hero primary с микрокопией «Вход через Google · без карты», шапка outline «Войти», spinner-состояние и aria-label при редиректе на OAuth.
