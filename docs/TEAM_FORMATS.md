# Командные турниры: встречи команд из одиночек, пар и микста

Решения владельца (2026-11-14): первая версия (MVP, 6 пунктов) + этапы расширения отдельными PR;
только теннис; состав на встречу ставят организатор и капитаны уже в MVP.

Источник спроса: ответы клубов LAW SLAM и Smūgio taškas (ноябрь 2026). Исследование форматов
(Кубок Дэвиса, United Cup, World TeamTennis, USTA League, Medenspiele, клубные лиги, LAW SLAM 2017,
литовский чемпионат клубов 2022): https://claude.ai/artifact/H3k2zBhFNMmSHGUNhB21mW.

## Термины

| Термин | lt | Что это |
|---|---|---|
| Команда | komanda | Заявка (`entries`) категории `team`; состав игроков — `entry_members` |
| Встреча | komandų susitikimas | Матч между двумя командами (`matches`, без `parent_match_id`) |
| Линия | mačas / linija | Один матч внутри встречи: одиночка, пара или микст (`matches` с `parent_match_id`, stage `rubber`) |
| Состав на встречу | susitikimo sudėtis | Кто играет каждую линию (`tie_lineups`) |
| Капитан | kapitonas | Пользователь, привязанный к команде (`team_captains`) |

## Где доступно

| Параметр | Значение |
|---|---|
| Спорт | только `tennis` (триггер `guard_team_category`) |
| Включение | флаг `feature.teams` (по умолчанию выключен; без него турнир категории `team` не создаётся — `team.disabled`) |
| Категория | `tournament_category = 'team'` (новое значение) |
| Форматы | `round_robin`, `groups_playoff`, `single_elimination`; `double_elimination` и форматы на очки — отказ `team.formatNotSupported` |
| Генераторы | существующие (`generate_round_robin`, `generate_groups`, `generate_group_playoff`, `generate_bracket`/`rebuild_bracket`) создают встречи, затем `create_tie_rubbers` — линии |

## Шаблон встречи: `format_config.tie`

```json
{
  "lines": [{"type": "MS"}, {"type": "WS"}, {"type": "XD"}],
  "win_rule": "rubbers",
  "decider": {"type": "AD"},
  "max_lines_per_player": {"singles": 1, "doubles": 1},
  "roster_min": 2,
  "roster_max": 16
}
```

- Типы линий: `MS` одиночка мужчины, `WS` одиночка женщины, `XS` одиночка любой, `MD` мужская пара,
  `WD` женская пара, `XD` микст (мужчина + женщина), `AD` пара любого состава. От 1 до 9 линий.
- `win_rule`: `rubbers` — побеждает больше выигранных линий; `games` — больше сумма геймов по всем линиям.
- Линии после решённого исхода («мёртвые») можно доиграть: при `rubbers` они меняют только разницу линий.
- `decider.type`: тип решающей линии при равенстве там, где ничья запрещена (плей-офф); по умолчанию `AD`.
  Играется по правилам турнира, как обычная линия (формат «только тай-брейк» — этап 5).
- Нормализует и проверяет шаблон `team_tie_config(jsonb)` (значения по умолчанию, `team.invalidTemplate`).
- Формат каждой линии в MVP общий для турнира: `set_format` + `scoring_config.tennis`.
- Очки в таблице: существующие `scoring_config.points_win/draw/loss`, для командной категории по умолчанию 2/1/0.
- Пресеты мастера: «2 одиночки + пара» (`XS, XS, AD`), «М + Ж + микст» (`MS, WS, XD`), «3 пары» (`AD×3`),
  «Чемпионат клубов» (`MD×3, WD, XD`), «Свой набор».
- Шаблон меняется только до генерации встреч (иначе `team.templateLocked`).

## Модель данных

- **Команда** = `entries` с `entry_type = 'team'`, `display_name` = название, контакт = контакт капитана.
- **Заявка команды** = `entry_members` (порядок `member_order` 1…N, до 30). CHECK `member_order in (1,2)` заменён
  на `member_order between 1 and 60` (31…60 — временный диапазон при перезаписи заявки) + триггер
  `guard_entry_member_count`: не больше 2 для не-командных заявок. `roster_max` проверяет `team_write_members`.
  Командная заявка создаётся только через `add_team_entry`/`register_team` (иначе `team.useTeamForm`). Новая колонка `entry_members.gender` (`male` | `female` | null) — нужна
  для линий `MS/WS/MD/WD/XD`.
- **Встреча** = обычная строка `matches` (стороны — команды). Канонический агрегат:
  `side_a_score/side_b_score` = выигранные линии (`rubbers`) или сумма геймов (`games`),
  `winner_entry_id`, `status`. Его читают доски, `tournamentChampion`, плей-офф, `propagate_winner`.
- **Линия** = строка `matches` с `parent_match_id` (FK на встречу, `on delete cascade`), `line_no`,
  `stage = 'rubber'` (новое значение), стороны зеркалят команды встречи, `round_number` = раунд встречи,
  `match_number` — сквозной номер линий турнира. Счёт линии — существующие `match_sets`,
  `update_match_sets`, live (`start_live_match`/`record_point`), исправления и W.O.
- **Состав** = `tie_lineups(id, tie_id, line_id, side 'A'|'B', slot 1|2, member_id)` +
  `tie_lineup_submissions(tie_id, side, tournament_id, submitted_at, submitted_by)`. Линия получает
  `status = 'ready'`, когда у обеих сторон есть игроки на неё (`refresh_tie_line_status`); счёт или live
  без состава — `team.lineupMissing`; счёт или live на самой встрече — `team.tieComputed`.
- **Капитаны** = `team_captains(entry_id, user_id, created_at)`, `team_captain_invites(entry_id, token_hash,
  created_by, created_at)` — одно открытое приглашение на команду, одноразовое, 30 дней; в БД только SHA-256.

## Счёт встречи

- Триггер `trg_team_rubber_changed` (AFTER UPDATE OF status, winner_entry_id, side_a_score, side_b_score
  на строках с `parent_match_id`) вызывает `recompute_tie(tie_id)`:
  - `rubbers`: счёт = число выигранных линий; исход решён, когда одна сторона выиграла больше половины линий шаблона.
  - `games`: счёт = сумма геймов сыгранных линий (решающий тай-брейк матча = 1 гейм); исход решён, когда сыграны все линии.
  - Пока ни одна линия не начата, счёт встречи `null`.
  - Исход решён → `winner_entry_id`, `status = 'finished'`, `propagate_winner(tie)` для плей-офф.
  - Все линии сыграны и равенство: в круге и группах — ничья (`winner_entry_id = null`, очки за ничью);
    в плей-офф — создаётся решающая линия (`decider`), встреча ждёт её.
  - Решающая линия существует, только пока встреча плей-офф равна после всех линий; ненужная (без результата) удаляется.
  - Исправление результата линии пересчитывает встречу. Изменился исход → `assert_score_correction_safe`
    (следующие встречи без результатов, иначе `scoringFlow.downstreamStarted`), `reset_correction_descendants`,
    `propagate_winner`. Встречу группы после построения плей-офф изменить нельзя (`scoringFlow.downstreamStarted`).
- Линии создаёт триггер `trg_team_tie_sides`, когда у встречи известны обе команды (генерация, `propagate_winner`).
  Смена команды до начала игры заменяет линии вместе с составами; при начатой линии — `team.tieHasResults`.

## Правила состава

- Игрок из заявки своей команды (`team.notInRoster`); не дважды в одной линии; не больше игроков, чем нужно линии
  (`team.invalidLineup`); лимиты `max_lines_per_player` по линиям шаблона, решающая линия не считается
  (`team.playerLineLimit`).
- Пол: `MS`/`MD` — мужчины, `WS`/`WD` — женщины, `XD` — мужчина и женщина; у игрока без пола такие линии
  недоступны (`team.genderMismatch`). `XS`/`AD` — любой состав.
- Частичный состав — черновик (`p_submit = false`); подача требует все линии (`team.lineupIncomplete`).
- Видимость (`tie_lineup_visible`, RLS и снимок): организатор и судья результатов видят всё; капитан — свою сторону;
  все, кто видит турнир, — обе стороны, когда обе поданы или на встрече началась игра.
- Капитан меняет свой состав до подачи и до начала игры (`team.lineupSubmitted`); организатор — пока линия
  не начата (`team.lineLocked`), и может вернуть капитану право правки (`reopen_tie_lineup`).
- Игрока, который уже играл линию, нельзя убрать из заявки (`team.memberPlayed`).

## Таблица

- `standings_rows` считает только встречи (`parent_match_id is null`). Для встречи: счёт = линии (или геймы),
  геймы и сеты — сумма сыгранных линий.
- Порядок: очки → личная встреча → разница счёта → разница сетов → разница геймов → счёт → геймы → посев → имя → id.
- `group_playoff_seeding` использует ту же функцию, поэтому посев плей-офф из групп работает без изменений.
- Ключи снимка `standings` / `group_standings` прежние (сигнатура `get_standings` не менялась).

## RPC

- `add_team_entry(p_tournament_id, p_team_name, p_members jsonb, p_contact, p_status)` — организатор, до старта.
- `register_team(p_slug, p_team_name, p_members jsonb, p_phone, p_email, p_access_token)` — публичная регистрация
  (видимость, статус, дедлайн, вместимость в командах, лист ожидания, оба контакта, дубли; `roster_min` —
  `team.rosterTooSmall`). Вошедший пользователь сразу становится капитаном.
- `save_team_roster(p_entry_id, p_members jsonb, p_team_name)` — организатор до завершения турнира, капитан до старта
  (`team.rosterLocked`). Элемент: `{id?, name, gender}`; `id` сохраняет игрока (его составы и рейтинги).
- `update_tie_template(p_tournament_id, p_tie)` — организатор, до генерации встреч.
- `create_captain_invite(p_entry_id)` → `{token}` (owner/editor); `claim_team_captain(p_token)` →
  `{entry_id, tournament_id, slug, team_name}` (вошедший пользователь; `team.inviteInvalid`);
  `remove_team_captain(p_entry_id, p_user_id)` (организатор — любого, капитан — себя);
  `list_team_captains(p_tournament_id)` → капитаны с email и именем (owner/editor).
- `save_tie_lineup(p_tie_id, p_side, p_lines jsonb, p_submit)` — `p_lines = [{line_no, members: [uuid…]}]`,
  организатор (owner/editor/counter) или капитан своей стороны; `reopen_tie_lineup(p_tie_id, p_side)`.
- Доступ: `is_team_captain(p_entry_id)`, `tie_lineup_visible(p_tie_id, p_side)`.
- Снимок `get_tournament_sync_state`: `entry_members[].gender`, `tie_lineups` (с фильтром видимости),
  `tie_submissions` (`tie_id, side, submitted_at`), `team_captains` (команды с капитаном), `my_captain_entries`
  (команды текущего пользователя); `matches[]` уже содержит `parent_match_id`/`line_no`.
  `tournament_entry_snapshot` (CAS редактора пар) тоже несёт `gender`.
- Realtime: `tie_lineups`, `tie_lineup_submissions` в публикации; сохранение состава и захват капитанства
  обновляют строку встречи / заявки, поэтому открытые страницы получают сигнал и без новых подписок.
- `list_my_tournaments` считает встречи, а не линии.

## Интерфейс

- Флаг `feature.teams` (вкладка «Другие» на /admin/platform) открывает категорию «Команды» в мастере (только теннис;
  при двойном выбывании и форматах на очки недоступна с подсказкой).
- Мастер, шаг «Правила игры»: `TieTemplateFields.vue` — пресеты, список матчей встречи, правило победы, решающий матч,
  размер команды. Настройки турнира: тот же блок, сохраняется `update_tie_template` до генерации встреч.
- Админка, «Участники»: «+ Добавить команду» и кнопка «Состав · N» у каждой команды открывают `TeamRosterModal.vue`
  (игроки и пол; для owner/editor — капитан и «Создать ссылку капитана»). Ручное добавление игроков и AI-импорт скрыты.
- Снимок разделяется на встречи и их матчи (`splitRubbers`): `matches` во всех досках, расписании и списках — только встречи,
  поэтому сетки, таблицы, расписание и чемпион работают без изменений.
- Встреча: `TieModal.vue` (админка и публичная страница) — счёт встречи, матчи с игроками и счётом, составы.
  Организатор задаёт составы обеих сторон (`TieLineupEditor.vue`, фильтр игроков по полу), открывает счёт или live матча
  (`MatchScoreModal` / `LiveScoringModal` получают матч с именами игроков — `labelledLine`). Капитан — свою сторону:
  черновик или подача. Открывается из ячейки кругового турнира, списка матчей, карточки сетки и матча группы.
- Вкладка «Счёт» командного турнира — список встреч (`TournamentMatchList`) вместо ввода сетов.
- Таблицы (`StandingsTable`, `RoundRobinStandings`, группы): столбцы И/В/Н/П/Матчи/О.
- Публичная регистрация (`RegistrationForm`): название команды, игроки с полом, телефон и email → `register_team`.
- Капитан (`CaptainPanel.vue` на `/tournaments/:slug`): ссылка `?captain=<token>`; вошедший пользователь подключается сразу,
  иначе «Войти через Google» сохраняет токен в localStorage (`lib/captainClaim.js`), Google возвращает в /admin,
  `App.vue` подключает и возвращает на страницу турнира. Панель: состав (до старта), «Мои встречи» с состоянием состава.
- Тексты: `src/i18n/teamFormat.js` (ru/en/lt/lv, ключ `team`), коды ошибок `team.*` → `team.errors.*`.

## Ограничения v1

- Только теннис; падел — этап 7.
- Форматы: круг, группы + плей-офф, олимпийка. Двойное выбывание команд — этап 5.
- Один формат матча на все линии; нет правил «порядок по силе» и очков по порогам — этап 5.
- Капитан не вносит счёт (только организатор и судья результатов) — этап 2.
- Капитан работает в публичных турнирах и турнирах по ссылке/паролю; в закрытых (private) — нет.
- Решающая линия играется по правилам турнира; вводит её состав организатор.
- Исправление линии, меняющее исход встречи, запрещено, если в следующих встречах уже есть результаты;
  встречи группы после построения плей-офф не меняются.
- Плата за участие: единица «команда» пока недоступна (только «игрок»).
- Нет жеребьёвки команд по уровням, суммы геймов с правилом «добить геймом» и супер-очка (формат LAW SLAM) — этап 3.
- Расписание по встречам, а не по линиям; автоматическое расписание считает встречу одним матчем по длительности
  (`match_minutes`), без учёта числа матчей и кортов встречи — этап 4.
- AI-создание не предлагает командную категорию; AI-импорт заявок команд — этап 6.
