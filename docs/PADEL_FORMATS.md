# Падл-форматы на очки: Americano, Mexicano, Team Americano, King of the Court

Решения владельца (2026-09-26): все четыре формата в одной итерации, матч играется
до суммы очков N (N настраивается), отдых компенсируется, живой счётчик очков сразу.

Правила по практике конкурентов (2026-09-27, `docs/PADEL_COMPETITORS.md`, исследование правил — `docs/PADEL_RULES_RESEARCH.md`): за отдых — половина
матча ⌊N/2⌋; раунд 1 Mexicano и King of the Court — жеребьёвка (посев — опция); при равенстве очков —
победы, ничьи, разница; King of the Court — число раундов задаётся до старта, Mexicano — без ограничения;
Americano — полный цикл партнёров по умолчанию.

## Форматы

| format | Участник | Расписание | Таблица |
|---|---|---|---|
| `americano` | игрок | всё сразу: полный цикл партнёров ⌊n(n−1)/2 ÷ (2·корты)⌋ раундов — каждый с каждым в паре, насколько позволяют корты; соперники с минимумом повторов | сумма очков игрока |
| `mexicano` | игрок | раунд 1 жеребьёвкой (или по посеву), затем каждый раунд по таблице: 1+4 против 2+3 на корте 1, 5+8 против 6+7 на корте 2 …; раундов сколько угодно, турнир завершает организатор | сумма очков игрока |
| `team_americano` | постоянная пара | круговая система (как round_robin) | сумма очков пары |
| `king_of_court` | игрок | раундов — заданное до старта число (`format_config.rounds`, по умолчанию корты + 3, не меньше 5); раунд 1 жеребьёвкой (или по посеву); дальше победители корта k поднимаются на k−1, проигравшие опускаются на k+1 (корт 1: победители остаются; последний корт: проигравшие остаются); на новом корте каждый поднявшийся играет в паре с опустившимся | корт последнего завершённого раунда → результат в нём → сумма очков |

Все четыре — только padel (`sportConfig.padel.allowedFormats`, серверный триггер `guard_points_format`).
Матчи турнира на очки создают только `generate_points_format` и `generate_next_round`: генераторы сетки,
круговой и групп (`generate_bracket`, `rebuild_bracket`, `generate_round_robin`, `generate_groups` …) отвечают
`pointsFormat.useRounds` (триггер `guard_points_format_matches`). Прямое удаление матчей админом
(«Сбросить сетку») разрешено только до старта: в идущем и завершённом турнире матчи и результаты остаются.

## Модель данных

- **Игрок = entry с одним участником.** Для индивидуальных форматов (`americano`, `mexicano`,
  `king_of_court`) триггер принудительно ставит `doubles_pairing_mode = 'pick_random'`:
  регистрация по одному, вместимость в людях. Второй участник в entry запрещён триггером
  на `entry_members` (формирование пар для этих форматов не применяется).
- **Партнёры в матче:** `matches.side_a2_entry_id`, `matches.side_b2_entry_id`. Для
  `team_americano` они пустые (сторона — пара). `winner_entry_id` = первый игрок победившей
  стороны; ничья → `null`.
- **Счёт:** `side_a_score/side_b_score` = набранные очки (канонический агрегат), без `match_sets`.
  Сумма обязана равняться `scoring_config.points_per_match` (N). Ничья возможна при чётном N.
  King of the Court требует нечётное N (у каждого матча есть победитель для перемещения).
- **Состав:** генератор пишет `format_config.roster` (uuid игроков/пар) и `format_config.courts`.
  Отдыхающие в раунде r = состав минус участники матчей раунда r. Проверка устаревшего состава
  перед стартом сравнивает одобренных с `roster`.
- **Компенсация отдыха:** за каждый завершённый раунд (все матчи finished), где участник отдыхал,
  он получает ⌊N/2⌋ — средний счёт матча (как «среднее раунда» у конкурентов), с первого же раунда.
  В базе не хранится — считается в таблице, колонка «Отдых».
- **Порядок таблицы:** сумма очков с компенсацией → победы → ничьи → разница очков → посев → имя.
  King of the Court: корт последнего завершённого раунда → победа в нём → далее как выше.
- **Раунд 1 Mexicano / King of the Court:** `format_config.first_round` = `random` (по умолчанию) или `seeded`.

## RPC

- `generate_points_format(p_tournament_id, p_rounds, p_courts, p_first_round)` — americano: всё расписание
  (`p_rounds` по умолчанию полный цикл партнёров), team_americano: круговая, mexicano/king_of_court: раунд 1
  (`p_first_round` = `random` | `seeded`; для king_of_court `p_rounds` — число раундов турнира, 2–30).
  Americano: при всех занятых кортах и 8, 12, 13, 16, 17, 20, 21, 24, 25 игроках — циклический whist-дизайн
  (каждый с каждым в паре ровно раз и против ровно дважды за цикл; таблицы найдены офлайн и проверены).
  Иначе — круговой метод (партнёры без повторов), если он держит разброс отдыха в пределах 1, либо
  построение раунд за раундом (отдыхают те, кто отдыхал меньше; среди равных играют те, у кого больше
  непройденных партнёров; пары и соперники с минимумом повторов). Когда раундов больше одного круга
  (полный цикл при отдыхах), круговые кандидаты соревнуются с пораундовыми; сохраняется расписание
  с наименьшим числом повторов партнёров, затем соперников.
- `generate_next_round(p_tournament_id)` — mexicano/king_of_court, когда текущий раунд завершён;
  king_of_court после последнего запланированного раунда отвечает `pointsFormat.lastRoundPlayed`.
- `undo_last_round(p_tournament_id)` — удалить последний раунд без результатов (mexicano/king_of_court).
- `update_match_points(p_match_id, p_a, p_b, p_expected_revision)` — ручной итог.
  В динамических форматах результат раунда нельзя менять, если уже есть следующий раунд.
- `get_points_standings(p_tournament_id)` → в снимке ключ `points_standings`.
- Живой счёт: `start_live_match`/`record_point`/`stop_live_match` ветвятся по формату:
  состояние `{family:'points', points:{a,b}, target:N, winner}`; при сумме N матч завершается.

## v1-ограничения

- King of the Court: число игроков кратно 4, минимум 8 (без отдыха).
- Americano: состав и число кортов фиксируются при генерации; замена игрока — перегенерация до старта.
- Нет смешанного Americano (М+Ж) и режима «первый до N» / по времени.
